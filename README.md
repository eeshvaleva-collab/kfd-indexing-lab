## Основное задание

### Решение

**Файл с реализацией `selectProducts`:**

[ProductSelection.kt](src/main/kotlin/lab2/ProductSelection.kt)

**Как работает функция и почему выбран такой способ обработки данных?**

Функция построена на ленивых вычислениях через Sequence, чтобы не создавать промежуточные коллекции при фильтрации и трансформации

**Как сохраняются порядок рекомендаций и уникальность товаров? Как обрабатываются исключённые, недоступные и неизвестные товары?**

Порядок сохраняется за счет того, что базой для Sequence выступает исходный список рекомендаций
Уникальность обеспечивается оператором .distinct()
исключённые товары отсекаются через .filter { it !in excludedSet }, 
неизвестные значения фильтруются на этапе маппинга с помощью .mapNotNull { currentMap[id] },
недоступные отсекаются проверкой .filter { it.available }

### Сложность

Обозначения:

- `p` — число товаров в каталоге;
- `r` — число идентификаторов в рекомендациях;
- `e` — число идентификаторов в исключениях.

**Время выполнения:**

`O(p) + O(r) + O(e) = O(p + r + e)`

Суммарное время выполнение зависит только от количества элементов в каждом объекте, так как все операции над ними выполняются за константное время
- итоговая сложность линейная

В теории худшем случае при возникновении коллизий (околонулевая вероятность особенно для лонга) сложность может возрасти до квадратичной
В лучшем случае, когда список рекомендаций пуст, сложность будет `O(p + e)`

**Дополнительная память:**
productMap займет `(O(p))` в памяти, сет исключений `O(e)`
сет distinct займет в памяти в худшем случае `O(r)`
и на итоговый список `O(min(p,r))`
В худшем случае выделится `O(p + r + e)`

Память для результата:
`O(min(p, r))` — память выделяется под финальный возвращаемый список, 
размер которого не может превышать количество уникальных рекомендаций или общее число товаров в каталоге

### Организация решения

**Файлы с реализацией и пример вызова:**

[ProductRecommendationService.kt](src/main/kotlin/lab2/ProductRecommendationService.kt)

```kotlin
ProductRecommendationService.loadCatalog(catalog)
val result = ProductRecommendationService.selectProducts(recommendedIds, excludedIds, limit = 2)
```

**Что выполняется при загрузке каталога, а что — при каждом запросе? Как обеспечиваются независимость запросов и переход на новый каталог?**

При загрузке каталога выполняется создание словаря (ассоциативного массива) на основе коллекции товаров с ключами = id товара
При каждом запросе выполняется снимок текущего состояния словаря, перевод списка исключений в хэш-сет и последующая ленивая фильтрация

Неизменность каталога внутри запроса обеспечивается за счет работы с локальным снимком каталога
Независимость запросов обеспечивается использованием локальных переменных внутри функции и иммутабельностью объектов
Переход на новый каталог происходит мгновенно при вызове `loadCatalog` за счет аннотации `@Volatile` на уровне свойства сервиса -
глобальная переменная мгновенно начинает указывать на другой адрес в памяти (новую мапу), и это изменение синхронно становится видимым для всех потоков

**Когда прекращается просмотр рекомендаций? От чего зависит число просмотренных элементов?**

Просмотр рекомендаций прекращается либо при нахождении необходимого количества (согласно лимиту) валидных товаров - досрочное завершение,
либо когда будет полностью просмотрен список рекомендаций, если к этому моменту нужное количество валидных товаров не наберется

Число просмотренных элементов напрямую зависит от распределения подходящих товаров в списке рекомендаций: 
конвейер будет запрашивать новые айди сверху, пока не заполнит лимит или не исчерпает список

### Сложность

Обозначения:

- `p` — число товаров в каталоге;
- `r` — число идентификаторов в рекомендациях;
- `e` — число идентификаторов в исключениях;
- `l` — значение параметра limit

| Этап | Время | Дополнительная память |
| --- | --- | --- |
| Подготовка каталога | O(p)| O(p) |
| Один запрос | O(r + e) | O(e + O(min(r, l)) |

**Обоснование оценок и память для результата:**

Подготовка каталога занимает `O(p)` времени и памяти на создание Map
На один запрос выделяется `O(e)` памяти под excludedSet 
Оператор .distinct() занимает в памяти максимум `O(min(r, limit))`
Память для результата составляет `O(limit) `(меньше, если подходящих товаров в каталоге не хватило)
